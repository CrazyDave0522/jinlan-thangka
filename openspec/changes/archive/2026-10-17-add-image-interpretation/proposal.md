## Why

Visitors can attach pictures, but the current endpoint declines image questions. This increment must explain visible subject/deities/style and identify a specific archived work when adequate linking evidence exists. Repeated visual processing of unrelated historical images wastes request capacity and model work.

## What Changes

- Support subject/deity/style interpretation, comparisons and evidence-supported identification of specific archive records. Include both readable-identifier and ordinary unnumbered-photo identification paths. Distinguish an identified record, tentative candidates, no matches and insufficient evidence; catalogue matching does not authenticate an object's genuineness.
- Keep the existing maximum of four new attachments per message. Limit distinct active visitor images to four per attempt, counting new attachments and explicitly selected historical pictures together; bounded server-selected archive reference images have a separate budget. Retain at most twenty distinct prepared attachments across the page, including completed/failed previews and the next draft; preserve the existing byte budgets as additional guards.
- Send current/explicitly selected images only. Reuse bounded prior observations in ordinary text follow-ups; offer “重看图片并回答” when new visual detail is needed, carrying the original question and specified pictures without replacing a newer draft. Keep unselected picture references and prior text visible without pretending to reread their bytes.
- Default to one selected-image analysis followed by text-only answering. Permit targeted comparison against authorized archive references in the second call when identification needs it; never resend all history or add a third model call. Retain at most two provider calls, up to four bounded queries for image-related groups and the accepted two-query limit for ordinary text-only requests.
- Preserve query/image-group provenance and image-to-record associations so four independent works can each receive a bounded search in one attempt. Keep visible facts, readings, interpretations and missing details separate, with one current observation version per image and no automatic promotion of uncertainty.
- Keep all visitor images and observation summaries page-local, with transient request processing, manual retry ownership, explicit failures and responsive Chinese presentation. No visitor Storage bucket, Files API or persisted conversation is introduced. Curated reference reads are server-only, rights-gated and restricted to configured project Storage assets; arbitrary remote image fetching remains prohibited.
- Add deterministic unit/component and real-route browser coverage, and a separately authorized real-image/record evaluation protocol.

Client, route, fixtures and canonical validation must change together; minimal text requests need explicit protocol opt-in, and unversioned stale requests fail before paid work; stale tabs fail safely until deliberate reload.

Existing structured archive retrieval supplies candidates; a bounded reference reader supports authorized curated images. Local fixtures do not create remote buckets or populate the owner archive.
